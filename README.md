# Repost News Bot

Бот для новостных Telegram-каналов (можно на несколько каналов сразу, каждый
на своём языке):

1. **Автоматически отслеживает** посты в каналах-источниках.
2. Переписывает текст своими словами (не построчный перевод) на нужный
   язык — русский или узбекский (кириллица), в зависимости от того, для
   какого канала готовится пост.
3. Подбирает похожее (но не то же самое) горизонтальное фото сразу в
   нескольких бесплатных фотостоках (Pexels, Pixabay, Openverse).
4. Если каналов несколько — сначала спрашивает, для какого канала готовить
   этот пост, затем присылает превью на модерацию с кнопками
   `✅ Опубликовать` / `🔄 Другое фото` / `❌ Отклонить` — и публикует в
   канал только после подтверждения.

Есть и ручной режим (дополнительная функция): можно самому переслать боту
пост (в личку или в группу, куда он добавлен) с командой `/rewrite` — он
пройдёт через тот же рерайт/перевод/подбор фото и превью.

## Почему для мониторинга нужен отдельный "юзер"-логин

Обычный Telegram-бот (Bot API) получает посты только из тех каналов, где
он сам добавлен администратором. Чтобы читать чужие публичные каналы, вход
нужен от имени обычного Telegram-аккаунта (это называется MTProto
user-сессия, библиотека Telethon) — как будто вы сами читаете эти каналы
в приложении. Это отдельный логин по номеру телефона, делается один раз.

## Установка

### 1. Базовая часть (бот, канал, LLM, фото)

1. Создайте бота через [@BotFather](https://t.me/BotFather) → `BOT_TOKEN`.
2. Добавьте бота администратором в каждый ваш канал (с правом отправки
   сообщений) и заполните для каждого свой блок `CHANNEL_N_*` в `.env`
   (`CHANNEL_1_ID`, `CHANNEL_2_ID`, ...) — подробности в `.env.example`.
   Для публичного канала id — `@username`, для приватного — числовой id
   вида `-1001234567890` (узнать можно через @getidsbot, переслав ему пост
   из канала).
3. Узнайте свой Telegram user id (например, через @userinfobot) →
   `ADMIN_IDS`. Через запятую, если модераторов несколько.
4. Ключ Gemini API → `GEMINI_API_KEY` — берётся на
   https://aistudio.google.com/apikey (обычный Google-аккаунт, без карты).
   Это отдельный бесплатный тариф именно API, не подписка Gemini
   Advanced/Google One — те не дают программного доступа. Модель задаётся
   через `GEMINI_MODEL`.
5. Ключ Pexels API → `PEXELS_API_KEY` (pexels.com/api, бесплатно).
   Опционально ещё `PIXABAY_API_KEY` (pixabay.com/api/docs) — Openverse
   подключён без ключа автоматически.

### 2. Автомониторинг каналов

1. Получите `API_ID` и `API_HASH` на https://my.telegram.org/apps (вход
   по своему номеру телефона).
2. Установите зависимости: `pip install -r requirements.txt`.
3. Запросите код входа:
   ```bash
   python scripts/telethon_login.py request <API_ID> <API_HASH> <телефон>
   ```
   Код придёт в приложение Telegram (или SMS).
4. Подтвердите код (если включена двухфакторная аутентификация — добавьте
   пароль последним аргументом):
   ```bash
   python scripts/telethon_login.py confirm <API_ID> <API_HASH> <телефон> <код> [пароль]
   ```
   Скрипт выведет строку — это `TELEGRAM_SESSION`.
5. Впишите в `.env`: `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`,
   `TELEGRAM_SESSION`, и `SOURCE_CHANNELS` (каналы-источники через запятую,
   например `@channel1,@channel2`).
6. Опционально: `MODERATION_CHAT_ID` — id группы, куда будут приходить
   превью на модерацию (если не задать, превью уйдут в личку каждому из
   `ADMIN_IDS`).

### 3. Запуск

```bash
pip install -r requirements.txt
python -m bot.main
```

Если `TELEGRAM_API_ID`/`TELEGRAM_API_HASH`/`TELEGRAM_SESSION`/
`SOURCE_CHANNELS` не заполнены — автомониторинг просто не запускается,
бот работает только в ручном режиме (`/rewrite`).

## Ограничения текущей версии

- Мониторятся только те каналы, которые указаны в `SOURCE_CHANNELS`
  (нельзя отслеживать вообще все каналы Telegram).
- Аккаунт, от которого получена `TELEGRAM_SESSION`, автоматически
  вступает в указанные каналы-источники (нужно для получения live-постов).
- Фото ищутся по ключевым словам среди бесплатных стоковых фото Pexels,
  а не произвольным поиском по интернету.
- `.env` и файл `*.session` содержат чувствительные данные — не
  коммитьте их (уже добавлены в `.gitignore`).
