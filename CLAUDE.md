# Контекст проекта

Репозиторий публичный: сюда нельзя писать секреты, содержимое `.env` и IP сервера.

## Пользователь и общение

- Владелец Telegram-канала **USHA GAP** с новостями Узбекистана. Публикует посты на узбекском (кириллица) и русском; ролики выкладывает в Reels/Shorts/TikTok.
- Общаемся по-русски, коротко и по делу. Пользователь сидит на Windows-ПК и часто присылает скриншоты.
- Не любит лишних вопросов и пинг-понга. Команды для сервера давай одним блоком, который можно скопировать целиком. Решения принимай сам, спрашивай только то, что действительно решает он.
- VPS находится **в США**, не в Узбекистане. IP и пароль пользователь сообщает в чате — в репозиторий их не записывать.

## Новостной бот — `bot/` (`python -m bot.main`)

Следит за каналами-источниками, переписывает посты через LLM, подбирает фото, присылает админу превью с кнопками и публикует в его канал.

- `main.py` — точка входа. Запускает вместе: aiogram-поллинг, планировщик, мониторинг и health-сервер, если задан `PORT`.
- `monitor.py` — Telethon user-сессия (`TELEGRAM_SESSION`). Ловит новые посты в источниках и отправляет превью **только владельцу источника** (`SourceConfig.owner_id`).
- `pipeline.py` — рерайт → фото → превью. `llm.py` — Gemini, ходит через Cloudflare Worker-прокси (`GEMINI_BASE_URL`): IP сервера попал под гео-блок Google. Есть ретраи и перебор моделей при 429/503 и таймаутах. Модель сама подбирает эмодзи, ключевые слова для фото и CTA-фразу «перешли другу».
- `formatting.py` — HTML поста: премиум-эмодзи (`<tg-emoji>`), CTA, подпись канала.
- `telethon_posting.py` — финальная публикация идёт **от Premium-аккаунта через Telethon**: Bot API не умеет custom emoji в каналах. Если Telethon не сработал, бот публикует через Bot API. После публикации ставятся реакции: Premium-аккаунт — ❤️🤬👎, аккаунты из `TELEGRAM_EXTRA_SESSIONS` — по ❤️.
- Хранилища в `data/`, папка в `.gitignore` — это боевое состояние:
  - `channels.json` и `sources.json` — у каждой записи есть `owner_id` и `uid`; кнопки адресуются по `uid`, а не по индексу;
  - `admins.json` — `AdminStore`; первый id из `ADMIN_IDS` становится супер-админом, остальными админами он управляет через `/admins`;
  - `pending.json` и `pending_media/` — очередь превью; переживает рестарт бота. Медиа превью висят в памяти процесса, поэтому, когда их набирается больше 200 МБ (`CACHE_LIMIT_BYTES` в `storage.py`), старые превью сбрасываются автоматически (и при старте тоже) — иначе сервер с 1 ГБ памяти убивает бота по OOM. Об автоочистке бот пишет всем админам в личку;
  - `scheduled.json` и `scheduled_media/` — отложенные посты.
- `handlers/` — `/rewrite`, `/channels`, `/sources`, `/scheduled`, `/admins`. Каждый админ видит только свои каналы, источники и посты, а обработчики проверяют владельца.

## Бот монтажа — `montage_bot/` (`python -m montage_bot.main`)

Отдельный бот со своим токеном (`MONTAGE_BOT_TOKEN`). Принимает озвучку и исходники, отдаёт готовый вертикальный ролик 720×1280 в стиле канала.

- Работает на Telethon в режиме бота: Bot API не даёт скачивать файлы больше 20 МБ.
- Сценарий в боте: `/new` → озвучка → язык RU/UZ → видео и фото → «Собрать» → проверка распознанного текста → mp4. Разовые настройки: `/setlogo` (PNG файлом) и `/setmusic`; файлы лежат в `data/montage/`.
- `transcribe.py` — Groq Whisper с таймкодами слов; параметр `language` указывать обязательно.
- `timeline.py` — формула канала: склейки по 3 с первые 15 с, дальше по 3–5 с, с подстройкой к началу слов.
- `selector.py` — берёт самые динамичные куски без повторов, по порядку рассказа. Если материала мало: зум и слоу-мо, для фото — Ken Burns.
- `sources.py` — ffprobe и анализ кадров: динамика и **поиск чужих водяных знаков**. Знак — это край, который неподвижен, пока камера движется.
- `render.py` — водяной знак у края обрезается, в центре закрашивается через `delogo`; горизонтальные исходники идут с размытым фоном; лого сверху (ширина 146, y=249); фоновая музыка на −25 dB.
- `subtitles.py` — субтитры рисуются в Pillow в стиле CapCut: белый капс Montserrat Bold, текущее слово на чёрной скруглённой плашке.
- На Windows запускается через `start_montage_windows.bat`.

## Бот просмотров — `views_bot/` (`python -m views_bot.main`)

Бот @ushagapuzbot со своим токеном. Он админ канала и на каждый новый пост делает **один drip-feed заказ** просмотров на soc-proof.su (`/api/v2`). Настройки по скрину владельца: услуга 728 «🇺🇿 Просмотры на пост», 65 × 20 запусков каждые 35 мин = 1300 просмотров примерно за 11 ч, около 13 ₽ на пост. Всё это задаётся в `.env` (`VIEWS_*`).

- Накручиваются все посты из `VIEWS_CHANNELS`. Лимита бюджета нет — владелец контролирует расход сам.
- **Альбом** приходит пачкой сообщений. Под альбомом Telegram показывает просмотры **последнего** из них (проверено на постах 982–983), поэтому бот ждёт 5 с и заказывает на максимальный id.
- `store.py` хранит `data/views/orders.json`. Пост помечается **до** запроса в панель: при падении посередине лучше пропустить пост, чем оплатить дважды.
- `panel.py` повторяет запрос, только если соединение не установилось. Если ответ просто не дошёл, повтора нет (мог бы купить дважды): админу уходит «проверь вручную».
- О каждом заказе, ошибке и балансе бот пишет админам из `ADMIN_IDS` (им нужно один раз нажать /start в боте). Команды: `/balance`, `/last` — последние заказы и их статус из панели.

## Сервер

- Ubuntu, Python 3.14. Рабочая ветка: `claude/uzbek-post-rewrite-bot-lshf0h`.
- **Новостной бот** — `/root/repost-news-bot`, свой `.venv` и `.env`, сервис `repost-bot.service`.
  **Деплоится сам**: `deploy-webhook.service` (порт 9000, `hooks.json`) на каждый push в рабочую ветку запускает `deploy.sh` — `git pull`, `pip install`, `systemctl restart repost-bot`. Значит, любой push в ветку сразу уходит в бой. Руками в этой папке ничего не делать, `.env` не править; читать оттуда можно только через `grep` нужных строк, не выводя значения.
- **Бот монтажа** — отдельная папка `/root/montage-bot`: свой клон этого же репо, свой `.venv`, свой `.env` (только переменные монтажа). Сервис `montage-bot.service`, юнит в `deploy/montage-bot.service`, уже нацелен на эту папку.
- **Бот просмотров** — так же, отдельная папка `/root/views-bot`: свой клон, `.venv` из `views_bot/requirements.txt`, свой `.env` (`BOT_TOKEN`, `SOCPROOF_API_KEY`, `VIEWS_CHANNELS`, `ADMIN_IDS`, `VIEWS_*`). Сервис `views-bot.service` (`deploy/views-bot.service`, `MemoryMax=200M`). Вебхук его **не** обновляет. Обновление: `cd /root/views-bot && git pull && .venv/bin/pip install -r views_bot/requirements.txt && systemctl restart views-bot`.
- Swap 2 ГБ (`/swapfile`, `vm.swappiness=10`), добавлен 29.10.2026.

## Как деплоить бота монтажа (первая установка)

```
apt install -y ffmpeg git python3-venv
git clone -b claude/uzbek-post-rewrite-bot-lshf0h https://github.com/distamov/repost-news-bot.git /root/montage-bot
cd /root/montage-bot && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
grep -E '^(TELEGRAM_API_ID|TELEGRAM_API_HASH|ADMIN_IDS)=' /root/repost-news-bot/.env > /root/montage-bot/.env
```
- Дописать в `/root/montage-bot/.env` строки `MONTAGE_BOT_TOKEN=` и `GROQ_API_KEY=`. Значения есть в локальном `.env` на ПК пользователя; их не печатать.
- Запуск:
```
cp /root/montage-bot/deploy/montage-bot.service /etc/systemd/system/ && systemctl daemon-reload && systemctl enable --now montage-bot && journalctl -u montage-bot -n 30 --no-pager
```
- Лого и музыка с ПК: `scp data/montage/logo.png data/montage/music.m4a root@<IP>:/root/montage-bot/data/montage/` (папку `data/montage` на сервере создать заранее).
- Обновление в дальнейшем — только в этой папке:
```
cd /root/montage-bot && git pull && .venv/bin/pip install -r requirements.txt && systemctl restart montage-bot
```

После деплоя проверь `systemctl status montage-bot` (`active (running)`, без перезапусков по кругу). Отдельно убедись, что `repost-bot` по-прежнему `active (running)` и не перезапускался.

## Грабли, на которые уже наступали

- В `TELEGRAM_SESSION` должна быть **ровно одна** session-строка. Доп. аккаунты для реакций — только в `TELEGRAM_EXTRA_SESSIONS`, через запятую. Если смешать, `struct.error` уронит бот в краш-луп.
- Приватный канал задаётся числовым id вида `-100…`. Старый `@username` после смены на инвайт-ссылку указывает на чужой канал, и бот получает «not a member».
- Остановка `repost-bot` может висеть до ~90 с, пока идёт загрузка через Telethon. Это нормально.
- Без `hachoir` Telethon криво отправляет вертикальное видео. Медиа в Telethon передаются именованными `BytesIO` (`photo.jpg` / `video.mp4`).
- `.env` целиком не выводить, секреты в чат не печатать. Пользователь уже несколько раз случайно присылал токены на скриншотах — в таких случаях напомни перевыпустить их.
- Один токен — один запущенный экземпляр бота. Перед запуском бота монтажа на сервере его нужно выключить на ПК.
- Groq без `language` распознаёт узбекский как азербайджанский.
